# Материалы для защиты

## 1. Задача

Определить по одному замеру телеметрии, относится ли запись к сетевому сбою. Целевой класс — уровень ERROR. Сравниваются логистическая регрессия и XGBoost. Признаки описывают состояние узла в момент замера.

## 2. Данные и подготовка

165 590 записей из 27 суточных файлов. Сбоев 736, или 0,444%. Все события ERROR сосредоточены в одном дне. Обязательные поля и числовые значения проверяются при загрузке и подготовке. Узлы train, validation и test попарно различны. В тесте 33 195 записей, из них 148 со сбоями.

## 3. Как запустить

Показать [схему конвейера](architecture.md) и запустить по [README](README.md) команду Docker с подключённой папкой артефактов. На выходе открыть автоматически сформированный `report.md` и показать две сохранённые модели. Повтор той же команды выдаёт путь к уже готовому комплекту.

## 4. Результаты эксперимента

Результаты контейнерного запуска на тестовых узлах после выбора порога на validation.

| Модель | Порог | Average precision | F1 | Ложные алерты | Пропуски |
|---|---:|---:|---:|---:|---:|
| Логистическая регрессия | 0,99 | 1,0000 | 1,0000 | 0 | 0 |
| XGBoost | 0,20 | 0,9994 | 0,9933 | 2 | 0 |

На этом наборе более сложная модель не улучшила качество. Для XGBoost снижение порога с 0,5 до 0,2 устранило один пропуск на тесте и добавило один ложный алерт.

## 5. Что показала проверка

Проект запускается локально и в Docker. Автоматические тесты проверяют повторный запуск, загрузку моделей, корректность разделения по узлам и отклонение некорректного входа. Опыт показывает качество обнаружения события на новых узлах из того же синтетического периода. Для проверки переноса на новые периоды нужна телеметрия нескольких независимых инцидентов.
