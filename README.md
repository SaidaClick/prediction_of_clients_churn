# Прогнозирование оттока абонентов

Индивидуальный проект по аналитике больших данных. Конвейер берёт историю использования услуг, обращения и телеметрию, рассчитывает признаки по абонентам и сравнивает логистическую регрессию с XGBoost. Цель — оценить риск ухода абонента в течение 16 дней начиная с 15 января 2026 года.

## Данные и оценка

В репозитории есть [синтетический набор XS](data/churn-xs.tar.gz) из домашней работы 5, генератор `tdg`, seed `20260827`. Архив содержит CDR, обращения, телеметрию, паспорт набора и метки `churn_truth.csv`. Конвейер читает архив напрямую. Расчёт использует доступные до даты прогноза разделы `raw`. Известный повреждённый раздел CDR указан в конфиге и отмечается в логе.

В выборку входят абоненты с наблюдаемой активностью до среза, которые к началу окна ещё не ушли. Метка означает, что уход произошёл внутри окна прогноза. История, признаки и даты ухода обрабатываются раздельно. Поля `retention_contact` и `churn_day_index` в модели не используются.

Данные делятся по абонентам на train, validation и test в отношении 60/20/20. На validation подбирается порог по F1. На test публикуются метрики при пороге 0.5 и при подобранном пороге.

## Локальный запуск

Нужны Python 3.12 и `uv`. На macOS для XGBoost требуется OpenMP (`brew install libomp`). Команды выполняются из корня репозитория.

```sh
uv venv --python 3.12
uv pip sync requirements.txt
uv run --no-project .venv/bin/python pipeline.py
```

Пути, дата среза, горизонт, параметры разбиения и моделей заданы в [config.json](config.json). Другой файл настроек можно передать через `--config`. Для переопределения путей есть флаги `--input` и `--output`.

## Запуск в Docker

```sh
docker build -t hw6-churn .
mkdir -p artifacts/churn-docker
docker run --rm --mount "type=bind,source=$PWD/artifacts/churn-docker,target=/app/artifacts" hw6-churn
```

Архив входит в образ. Подключённая папка сохраняет результаты после завершения контейнера.

## Артефакты

Результаты сохраняются в каталоге с ключом запуска. Путь выводится в лог. При повторах с неизменными данными, кодом и настройками в той же среде используется существующий комплект.

| Файл | Содержание |
|---|---|
| `prepared.parquet` | Признаки, целевая метка и выборка каждого абонента |
| `logistic_regression.joblib` | Логистическая регрессия вместе с масштабированием |
| `xgboost.json` | Обученная модель XGBoost |
| `metrics.json` | Окно прогноза, состав выборок, признаки, пороги и метрики |
| `report.md` | Обзор данных и сравнение моделей |

## Проверки и ограничения

```sh
uv run --no-project .venv/bin/python -m unittest -v
```

Тесты проверяют границы окна, входной архив, повторный запуск и загрузку моделей. Обработка пакетная, на CPU и в памяти одного процесса. Набор охватывает один синтетический месяц, а проверка выполнена на других абонентах того же среза.
