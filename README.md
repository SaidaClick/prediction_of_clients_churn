# Обнаружение сбоев по сетевой телеметрии

Индивидуальный проект по аналитике больших данных. Конвейер пакетно обрабатывает телеметрию сетевых узлов и сравнивает логистическую регрессию с XGBoost. Целевой класс — запись уровня `ERROR`. Признаки включают нагрузку, число активных сессий, долю ошибок, задержку, температуру и час замера. Разбиение по `node_id` позволяет оценить модели на узлах, которых они не видели при обучении.

## Данные

В проект включён [подготовленный набор XS](data/telemetry-xs.tar.gz) с синтетической телеметрией из домашнего задания 5.2, генератор `tdg`, seed `20260827`. В архиве 27 суточных файлов `raw/telemetry/dt=*/telemetry.jsonl`. Конвейер читает архив напрямую. В выборку входят разделы исходного слоя `raw`, как в ноутбуке 5.2.

## Локальный запуск

Нужны Python 3.12 и `uv`. На macOS XGBoost также требуется OpenMP (`brew install libomp`). Команды выполняются из папки `hw6`.

```sh
uv venv --python 3.12
uv pip sync requirements.txt
uv run --no-project .venv/bin/python pipeline.py
```

Параметры запуска и моделей находятся в [config.json](config.json). Чтобы изменить их для эксперимента, можно передать другой файл через `--config`. Флаги `--input` и `--output` переопределяют пути к архиву и артефактам. Ключевые стадии пишут логи в терминал.

## Запуск в Docker

```sh
docker build -t hw6-telemetry .
mkdir -p artifacts
docker run --rm --mount "type=bind,source=$PWD/artifacts,target=/app/artifacts" hw6-telemetry
```

Архив входит в образ. Подключённая папка `artifacts` сохраняет результаты на компьютере после завершения контейнера.

## Результаты

Конвейер печатает путь `artifacts/<ключ запуска>/`. Ключ зависит от входного архива, параметров, кода и среды. Повторный запуск в той же среде использует тот же комплект.

| Артефакт | Содержание |
|---|---|
| `prepared.parquet` | Подготовленные признаки, целевая метка и принадлежность к выборке |
| `logistic_regression.joblib` | Логистическая регрессия вместе с масштабированием признаков |
| `xgboost.json` | Обученная модель XGBoost |
| `metrics.json` | Валидационные и тестовые метрики, выбранные пороги и стоимость ошибок при выборе порога |
| `report.md` | Обзор данных по дням и выборкам, сравнение моделей, ограничения |

Основная метрика для редких событий — average precision, обозначенная в работе как PR-AUC. Для каждой модели порог подбирается на валидации. Пропуск сбоя оценивается в 5000 условных единиц, ложная тревога — в 500. На тесте приведены результаты при пороге 0.5 и при подобранном пороге.

## Проверки и ограничения

```sh
uv run --no-project .venv/bin/python -m unittest -v
```

Тесты проверяют повторный запуск, состав артефактов, загрузку моделей, разбиение по узлам и отклонение некорректных входных данных. Пакетная обработка выполняется на одном компьютере в памяти. Данные синтетические, а все сбои в этом наборе относятся к одному дню. Проверка показывает, как модели обнаруживают уже наблюдаемый сбой на ранее не виденных узлах из того же периода. Для оценки качества на будущих периодах нужны данные о независимых инцидентах.
