# рефакторинг


| Функция | Что делает |
|---|---|
| `load_data` | Читает суточные разделы JSONL из архива и проверяет наличие обязательных полей |
| `preprocess` | Удаляет дубликаты, проверяет значения, извлекает час замера и размечает сбои по `level`. Делит данные на train, validation и test по узлам |
| `train_model` | Обучает логистическую регрессию с масштабированием и XGBoost на train |
| `evaluate` | Проверяет прогнозы и считает ROC-AUC, average precision, precision, recall, F1 и матрицу ошибок |

Точка входа запускает стадии по порядку и пишет в журнал количество записей, размеры выборок, обучение моделей, результаты оценки и путь к артефактам.

## Конфигурация и аналитические решения

В `config.json` вынесены пути, список признаков, seed, параметры разбиения и обеих моделей, сетка порогов и стоимости пропуска события и ложного алерта. Версии Python-пакетов закреплены в `requirements.txt`.

В XGBoost используются гиперпараметры, выбранные на обучающей выборке в домашней работе 5.2. Отдельные эксперименты с поиском параметров и SHAP остались в ноутбуке. В конвейере порог независимо подбирается для каждой модели на validation. Стоимость ошибок помогает явно сравнивать пропущенные сбои и ложные алерты, а test используется только для итоговой оценки.

## Повторный запуск и сохранение файлов

Ключ результата вычисляется из SHA-256 входного архива, аналитических настроек, исходного кода, списка версий пакетов и среды запуска. При совпадении ключа конвейер возвращает существующий каталог. Поэтому повторный запуск с теми же входами не добавляет строки и не создаёт лишние копии моделей. Смена данных или настроек даёт новый каталог.

Результаты записываются во временную директорию рядом с итоговой. После сохранения всех файлов она переименовывается в итоговый каталог. При сбое записи повторный запуск может сформировать комплект заново. Если два процесса одновременно готовят один результат, сохраняется первый полностью записанный комплект.

## Сложности

- Сбой — редкий класс, а все записи уровня ERROR относятся к одному дню. Сохранили групповое разбиение по узлам и добавили обязательную проверку, что в каждой выборке есть оба класса, а узлы не пересекаются. Качество на иных периодах предстоит проверять на нескольких независимых инцидентах.
- Ошибки и задержки измеряются в момент события. Высокие оценки описывают обнаружение текущего сбоя. Для проверки раннего предупреждения понадобятся предшествующие замеры и другой протокол оценки.
